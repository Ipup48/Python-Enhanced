คนตามแก้โค้ดเหนื่อยที่สุด เพราะต้องแก้ if-elif ก้อนเดิมทุกครั้งที่มีช่องทางใหม่

ถอดรหัสวิธีคิดของคนสำเร็จ:

  • เรียกเมธอดเดียวกันแต่ให้แต่ละวัตถุ dispatch พฤติกรรมของตนเอง (Polymorphism)
  • ห้ามตรวจชนิดด้วย isinstance — มันคือสัญญาณว่าระบบ “ปิด” รับการขยาย
  • ห่อ “ช่องทางที่งอกเรื่อย ๆ” ด้วย interface ที่มั่นคง (Protected Variations)
  • ประกอบระบบจากชิ้นส่วนเล็ก ๆ (Composition) — Notifier ถือลิสต์ของ channel

    def notify(self, channel, recipient: str, message: str) -> None:

1) เหตุใดการ “ข้ามเงียบ ๆ” จึงอันตรายกว่าการพังเสียงดัง และใครคือคนที่รับผลโดยไม่รู้ว่าระบบพลาด

เพราะไม่มีการตรวจสอบหรือแจ้งเตือนเมื่อเจอ channel ที่ไม่รู้จัก
นักศึกษาที่ควรได้รับข้อความคือคนที่รับผลโดยไม่รู้ว่าระบบพลาดไปแล้ว

2) คุณจะออกแบบอย่างไรให้ “การลืมช่องทางใหม่เป็นไปไม่ได้เลย” (ระบบต้องส่งเสียงเมื่อเจอสิ่งที่ไม่รู้จัก หรือบังคับให้รองรับตั้งแต่แรก)

ใช้ ABC (NotificationChannel) บังคับให้ทุก channel implement send()
แล้วให้ Notifier เรียก send() ผ่าน list โดยไม่ต้องตรวจชนิดเลย

3) ลองให้ AI เสนอวิธีกำจัด if-isinstance ในโค้ดนี้มา 3 วิธี แล้วถกกับเพื่อน: วิธีใดน่าเชื่อถือที่สุด และคำตอบของ AI เชื่อถือได้มากน้อยเพียงใด (ฟังเพื่อนให้จบก่อนสรุปนะ)

AI มักเสนอ Polymorphism ผ่าน ABC, Strategy Pattern หรือ Registry Pattern
แต่ควรถกกับเพื่อนว่าวิธีใดเหมาะกับขนาดของระบบจริงที่สุดก่อนสรุป
📦 กล่องความรู้เสริม (อ่านเฉพาะเมื่อจำเป็น):
  • Polymorphism: เรียกเมธอดเดียวกัน แต่แต่ละวัตถุ dispatch ไปยังพฤติกรรมของตนเอง
  • OCP: เพิ่มช่องทางใหม่ = เพิ่มคลาสใหม่ โดย Notifier ไม่ต้องแก้ไข
  • DIP: Notifier พึ่งพา abstraction (NotificationChannel) ไม่ใช่ concrete class
  • Composition: Notifier ประกอบขึ้นจากลิสต์ของ channel (list) ส่งได้หลายช่องทางพร้อมกัน
  • Protected Variations: ห่อหุ้ม “ช่องทางที่งอกเรื่อย ๆ” ด้วย ABC ที่มั่นคง
  • ทำไม isinstance จึงแย่: ผิด polymorphism, ทำให้ระบบปิดรับการขยาย, และข้ามสิ่งที่ไม่รู้จักอย่างเงียบ ๆ

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) «ABC» NotificationChannel ที่มีเมธอด +send(recipient, message) : None ทำหน้าที่อะไรในระบบ 2 คะแนน

NotificationChannel เป็นสัญญากลางที่บังคับให้ทุกช่องทางแจ้งเตือนมีเมธอด send()
เพื่อให้ Notifier เรียกใช้งานทุกช่องทางแบบเดียวกันได้

2) เหตุใด EmailChannel และ SmsChannel จึงเสียบเข้ากับ Notifier เดียวกันได้ สอดคล้องกับแนวคิดใด 2 คะแนน

เพราะทั้งสองคลาสสืบทอดและ implement ABC เดียวกัน (NotificationChannel)
สอดคล้องกับแนวคิด Polymorphism และ Dependency Inversion

3) ลูกศร “sends” จาก Notifier ไปยัง NotificationChannel หมายถึงอะไร และเหตุใด Notifier จึงเก็บ channels เป็น list[NotificationChannel] 2 คะแนน

หมายถึง Notifier ส่งข้อความผ่านแต่ละ channel โดยไม่รู้รายละเอียดภายใน
เก็บเป็น list เพื่อให้ส่งได้หลายช่องทางพร้อมกันและเพิ่มช่องทางใหม่ได้ง่าย

4) ลูกศร “raises” ชี้ไปยัง ValueError หมายถึงการตรวจสอบใด และเหตุใดจึงใช้ message.strip() ในการตรวจสอบ 2 คะแนน

หมายถึงการตรวจสอบว่าข้อความต้องไม่ว่างเปล่า ใช้ strip() เพื่อกันข้อความที่มีแต่ช่องว่างด้วย

5) เหตุใด Notifier จึงห้ามตรวจสอบชนิดของ Channel ด้วย isinstance 1 คะแนน

เพราะ isinstance ทำลาย Polymorphism และทำให้ระบบปิดรับการขยายช่องทางใหม่

6) หากต้องการเพิ่ม LineChannel ในอนาคต โค้ดส่วนใดต้องแก้ไขบ้าง (OCP) 1 คะแนน

เพิ่มคลาส LineChannel(NotificationChannel) ใหม่เท่านั้น ไม่ต้องแก้ Notifier เลย

7) การที่ Notifier ไม่จำเป็นต้องแก้ไขโค้ดเมื่อมีช่องทางใหม่ สะท้อนหัวใจสำคัญของ Open/Closed Principle อย่างไร 1 คะแนน

สะท้อนหลักการ Open for Extension (เปิดรับการขยายโดยเพิ่มคลาสใหม่)
และ Closed for Modification (ปิดการแก้ไขโค้ดแกนกลางที่มีอยู่เดิม)

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

from abc import ABC, abstractmethod
from typing import Iterable


class NotificationChannel(ABC):
    @abstractmethod
    def send(self, recipient: str, message: str) -> None: ...


class EmailChannel(NotificationChannel):
    def send(self, recipient: str, message: str) -> None:
        print(f"[Email] ถึง: {recipient} | ข้อความ: {message}")


class SmsChannel(NotificationChannel):
    def send(self, recipient: str, message: str) -> None:
        print(f"[SMS] ถึง: {recipient} | ข้อความ: {message}")


class Notifier:
    def __init__(self, channels: Iterable[NotificationChannel]):
        self._channels = list(channels)

    def notify(self, recipient: str, message: str) -> None:
        if not message.strip():
            raise ValueError("Message cannot be empty.")
        for channel in self._channels:
            channel.send(recipient, message)


notifier = Notifier([EmailChannel(), SmsChannel()])

# Test case 1: ส่งข้อความสำเร็จ
notifier.notify("student@example.ac.th", "มีการบ้าน PHP กำหนดส่งวันศุกร์นี้")

# Test case 2: ข้อความว่างต้องถูกปฏิเสธ
try:
    notifier.notify("student@example.ac.th", "   ")
except ValueError as e:
    print("Expected error:", e)

1) โค้ดบรรทัดใดแสดงให้เห็นว่า Notifier ไม่ผูกติดกับ concrete channel จงอธิบาย 2 คะแนน

บรรทัด channel.send(recipient, message) ใน for loop แสดงว่า Notifier ไม่ผูกติดกับ concrete channel
เพราะเรียกผ่าน interface เดียวโดยไม่สนใจว่าเป็น channel ชนิดใด

2) เมื่อเรียก notify ใน Test case 1 ผลลัพธ์ที่แสดงบนหน้าจอคืออะไรบ้าง 3 คะแนน

แสดงผล [Email] ถึง: student@example.ac.th | ข้อความ: มีการบ้าน PHP กำหนดส่งวันศุกร์นี้
ตามด้วย [SMS] ถึง: student@example.ac.th | ข้อความ: มีการบ้าน PHP กำหนดส่งวันศุกร์นี้

3) การเรียก notify ด้วยข้อความ ' ' จะเกิดอะไรขึ้น เพราะเหตุใด 2 คะแนน

จะเกิด ValueError('Message cannot be empty.') เพราะ strip() ทำให้ข้อความว่างเปล่าถูกตรวจจับได้

4) หาก Notifier ใช้ if isinstance(channel, EmailChannel): เพื่อเลือกวิธีส่ง จะผิดหลักการใด และส่งผลเสียอย่างไร 3 คะแนน

ผิดหลัก OCP และ Polymorphism เพราะเพิ่ม channel ใหม่ต้องแก้โค้ดเดิมทุกครั้ง
ทำให้ระบบเสี่ยงต่อ regression และดูแลรักษายากขึ้นเรื่อย ๆ

ส่วนที่ 5: สะท้อนคิดเชิงออกแบบ OOAD (6 คะแนน)

1) ระบบนี้สอดคล้องกับ Open/Closed Principle อย่างไร จงยกตัวอย่างการเพิ่มช่องทางใหม่ 2 คะแนน

สอดคล้องกับ OCP เพราะเพิ่ม LineChannel(NotificationChannel) ใหม่ได้ทันที
โดยไม่ต้องแก้โค้ด Notifier เดิมแม้แต่บรรทัดเดียว

2) “จุดที่เปลี่ยนแปลง” ในข้อนี้คืออะไร และการออกแบบนี้ปกป้อง Notifier ด้วย Protected Variations อย่างไร 2 คะแนน

จุดที่เปลี่ยนแปลงคือช่องทางแจ้งเตือน ถูกปกป้องด้วย ABC NotificationChannel
ทำให้ Notifier ไม่ต้องรู้จักช่องทางใหม่ที่จะเพิ่มเข้ามาในอนาคต

3) การใช้ list ร่วมกับ for loop และเรียก send() ผ่าน ABC ดีกว่าการตรวจชนิดของแต่ละ channel อย่างไร จงอธิบายด้วยแนวคิด Polymorphism 2 คะแนน

ดีกว่าเพราะเรียก send() เดียวกันได้กับทุก channel โดยไม่ต้องเพิ่ม if ใหม่ทุกครั้ง
แต่ละวัตถุ dispatch พฤติกรรมของตัวเองตามหลัก Polymorphism
