Feeling คืนก่อนวันงานใหญ่

ทีมประชาสัมพันธ์ต้องสั่งพิมพ์สื่อทุกชิ้นก่อนงานวันเดียว สมาชิกใหม่เขียนโค้ดคำนวณพื้นที่รวม ด้วย if-elif ตรวจชนิดรูปทรงทีละแบบ แต่ไม่มีใครรู้ว่าสัปดาห์ก่อนชมรมเพิ่งเพิ่ม “ป้ายทรงสามเหลี่ยม” เข้ามา — โค้ดจึง ข้ามมันไปอย่างเงียบ ๆ ผลคือสั่งวัสดุไม่พอ ทีมต้องอยู่แก้งานถึงตีสาม และเกือบพลาดงานใหญ่

1) คุณรู้สึกอย่างไรกับ “ความเงียบ” ของโค้ดที่ข้ามรูปทรงใหม่ไปโดยไม่บอกใคร และน่ากลัวกว่าการพังเสียงดังอย่างไร

ความเงียบน่ากลัวกว่าเพราะไม่มีสัญญาณเตือนให้รู้ตัวเลย
กว่าจะรู้ตัวก็สายเกินไป ต่างจากโค้ดพังแบบมี error ที่เห็นและแก้ได้ทันที

2) หากชมรมเพิ่มรูปทรงใหม่ทุกเดือน ใครจะต้องเหนื่อยที่สุด — คนออกแบบโค้ด หรือคนตามแก้โค้ด

คนตามแก้โค้ดเหนื่อยที่สุด เพราะต้องไล่หา if-elif ทุกจุดที่กระจายอยู่ทั่วระบบ

เรื่องเล่าจากพี่เลี้ยง: “isinstance 27 แห่ง”

พี่ฝน — Senior Engineer ใน software house แห่งหนึ่ง เล่าว่าโค้ดระบบคำนวณค่าพิมพ์ของลูกค้า มี isinstance กระจายอยู่ 27 แห่ง ทุกครั้งที่ลูกค้าเพิ่มรูปทรงใหม่ ทีมต้องตามแก้ทั้ง 27 แห่ง และพลาดอย่างน้อย 1 แห่งเสมอ จนวันหนึ่งเธอตัดสินใจ refactor ให้ “วัตถุตอบเองว่าพื้นที่เท่าไร” ผ่าน ABC เดียว — ตั้งแต่นั้นการเพิ่มรูปทรงใหม่ ใช้เวลาไม่ถึงชั่วโมงและไม่เกิด regression อีกเลย “อย่าถามวัตถุว่ามันคืออะไร จงบอกให้มันทำหน้าที่ของมัน”

ถอดรหัสวิธีคิดของคนสำเร็จ:

  • ออกแบบให้ “การเพิ่มของใหม่” ไม่ต้องแตะโค้ดเดิม (Open/Closed Principle)
  • ทำให้คลาสลูกทุกตัวแทนที่สัญญา (ABC) ได้อย่างถูกต้อง (Liskov Substitution)
  • ให้โค้ดระดับสูงพึ่งพา abstraction ไม่ใช่ concrete class (Dependency Inversion)

Finding Sandbox: โค้ดที่ “เงียบเกินไป”

ทัศนคติประจำใบงาน: Failure is learning — ผิดหรือถูกไม่สำคัญ นี่คือการทดลองเพื่อเติบโต

พิจารณาโค้ดต่อไปนี้ แล้วเติม Triangle เข้าไปในจินตนาการของคุณ

import math

class Circle:
    def __init__(self, radius: float):
        self._radius = radius

    def area(self) -> float:
        return math.pi * self._radius ** 2


class Rectangle:
    def __init__(self, width: float, height: float):
        self._width = width
        self._height = height

    def area(self) -> float:
        return self._width * self._height


def total_area(shapes) -> float:
    total = 0.0
    for shape in shapes:
        if isinstance(shape, Circle):
            total += shape.area()
        elif isinstance(shape, Rectangle):
            total += shape.area()
        # แล้ว Triangle ล่ะ? ...ถูกข้ามไปเงียบ ๆ!
    return total

1) หากเพิ่ม Triangle เข้าในระบบ ผลลัพธ์จะเป็นอย่างไร และเหตุใดความผิดพลาดแบบนี้จึงถูกค้นพบยาก

Triangle จะถูกข้ามไปเงียบ ๆ พื้นที่รวมผิดโดยไม่มี error ใด ๆ เกิดขึ้นเลย
จึงค้นพบยาก เพราะโปรแกรมยังรันผ่านได้ปกติทุกครั้ง

2) คุณจะออกแบบอย่างไรให้ “การลืมรูปทรงใหม่” เป็นไปไม่ได้เลย (ทำให้ระบบส่งเสียงเมื่อมีสิ่งที่ไม่รู้จัก)

เปลี่ยนจาก if-isinstance เป็น ABC ที่บังคับ subclass ต้อง implement area()
ถ้าลืม implement จะสร้างวัตถุไม่ได้ทันที (error ตั้งแต่ก่อนรัน)

3) ลองให้ AI เสนอวิธีกำจัด if-isinstance ในโค้ดนี้มา 3 วิธี แล้วถกกับเพื่อน: วิธีใดน่าเชื่อถือที่สุด และคำตอบของ AI เชื่อถือได้มากน้อยเพียงใด (ฟังเพื่อนให้จบก่อนสรุปนะ)

AI มักเสนอ ABC/Polymorphism, Strategy Pattern และ Factory ซึ่งน่าเชื่อถือ
แต่ควรฟังเพื่อนและตรวจกับบริบทจริงก่อนเชื่อคำตอบของ AI ทั้งหมด
📦 กล่องความรู้เสริม (อ่านเฉพาะเมื่อจำเป็น):
  • ABC + @abstractmethod: สัญญาที่บังคับให้ subclass ต้อง implement เมธอด มิเช่นนั้นสร้างวัตถุไม่ได้
  • Polymorphism / Duck Typing: เรียกเมธอดเดียวกัน แต่แต่ละวัตถุ dispatch ไปยัง implementation ของตนเอง
  • OCP: เปิดรับส่วนขยายใหม่ (เพิ่มคลาส) แต่ปิดรับการแก้ไขโค้ดเดิม
  • LSP: คลาสลูกต้องแทนที่ ABC ได้อย่างถูกต้องตามสัญญา
  • Validation ตอนสร้าง: ตรวจค่าใน __init__ เพื่อป้องกันวัตถุที่ไม่ถูกต้อง (fail fast)

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) «ABC» ที่กำกับคลาส Shape หมายถึงอะไรใน Python และ @abstractmethod มีบทบาทอย่างไร 2 คะแนน

ABC คือคลาสต้นแบบที่สร้างวัตถุตรง ๆ ไม่ได้ ใช้กำหนดสัญญาให้คลาสลูก
@abstractmethod บังคับให้ subclass ต้อง implement เมธอดนั้น มิเช่นนั้นสร้างวัตถุไม่ได้

2) ลูกศร “implements” จาก Circle และ Rectangle ชี้ไปยัง Shape หมายถึงอะไรในเชิงโค้ด Python 2 คะแนน

หมายถึง Circle และ Rectangle สืบทอด (inherit) จาก Shape
และต้อง override เมธอด area() ตามสัญญาที่ ABC กำหนดไว้

3) เหตุใดโค้ดหลักจึงไม่ต้องใช้ if หรือ isinstance ตรวจชนิดของคลาสก่อนเรียก area() 2 คะแนน

เพราะทุกคลาสลูกรับประกันว่ามีเมธอด area() เหมือนกันผ่าน Polymorphism
โค้ดหลักจึงเรียก shape.area() ได้ทันทีโดยไม่ต้องตรวจชนิดก่อน

4) การเก็บข้อมูลเป็น _radius, _width, _height พร้อมตรวจสอบค่าใน __init__ มีประโยชน์อย่างไร 2 คะแนน

ป้องกันการเข้าถึงข้อมูลโดยตรงจากภายนอก (encapsulation)
การตรวจค่าใน __init__ ช่วยป้องกันวัตถุที่มีค่าไม่ถูกต้องตั้งแต่ต้น (fail fast)

5) หากต้องการเพิ่มรูปทรง Triangle ในอนาคต โค้ดส่วนใดต้องแก้ไขบ้าง (OCP) 1 คะแนน

เพิ่มคลาส Triangle(Shape) ใหม่เท่านั้น ไม่ต้องแก้โค้ดเดิมที่มีอยู่เลย (OCP)

6) หากสร้างคลาสที่สืบทอด Shape แต่ไม่ implement เมธอด area() จะเกิดอะไรขึ้นเมื่อพยายามสร้างวัตถุ 1 คะแนน

จะเกิด TypeError ทันที เพราะยังไม่ implement เมธอด abstract ที่บังคับไว้

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

from abc import ABC, abstractmethod
import math


class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...


class Circle(Shape):
    def __init__(self, radius: float):
        if radius < 0:
            raise ValueError("Radius cannot be negative.")
        self._radius = radius

    def area(self) -> float:
        return math.pi * self._radius ** 2


class Rectangle(Shape):
    def __init__(self, width: float, height: float):
        if width < 0 or height < 0:
            raise ValueError("Width and height cannot be negative.")
        self._width = width
        self._height = height

    def area(self) -> float:
        return self._width * self._height


promotion_media = [Circle(0.10), Rectangle(1.20, 0.80)]
total_area = sum(shape.area() for shape in promotion_media)
print(f"พื้นที่สื่อประชาสัมพันธ์รวม: {total_area:.2f} ตารางเมตร")

1) บรรทัดใดในโค้ดหลักที่แสดง Polymorphism จงอธิบายการทำงาน 3 คะแนน

บรรทัด shape.area() ภายใน sum(...) แสดง Polymorphism
เพราะเรียกเมธอดเดียวกันแต่ Circle และ Rectangle ทำงานตามของตัวเอง

2) จงคำนวณพื้นที่ของ Circle รัศมี 0.10 และ Rectangle ขนาด 1.20 × 0.80 แล้วหาพื้นที่รวม (แสดงวิธีทำ) 3 คะแนน

Circle: 3.14 × 0.10² ≈ 0.0314 ตร.ม., Rectangle: 1.20 × 0.80 = 0.96 ตร.ม.
รวมพื้นที่ทั้งหมด ≈ 0.9914 ตารางเมตร

3) การเรียก Circle(-5) จะเกิดอะไรขึ้น และเหตุใดจึงต้องตรวจสอบค่าใน __init__ 2 คะแนน

จะเกิด ValueError('Radius cannot be negative.')
เพราะ __init__ ต้องตรวจค่าก่อนสร้างวัตถุ เพื่อป้องกันวัตถุที่ไม่ถูกต้องตั้งแต่ต้น

4) หาก Circle ไม่สืบทอด Shape แต่ยังมีเมธอด area() อยู่ โค้ดหลักจะยังทำงานได้หรือไม่ เพราะแนวคิดใดของ Python 2 คะแนน

ยังทำงานได้ เพราะ Python ใช้แนวคิด Duck Typing
ไม่จำเป็นต้องสืบทอดจริง ขอเพียงมีเมธอด area() ที่เรียกใช้ได้

ส่วนที่ 5: สะท้อนคิดเชิงออกแบบ OOAD (6 คะแนน)

1) ระบบนี้สอดคล้องกับ Open/Closed Principle อย่างไร หากเพิ่ม Triangle โค้ดหลักต้องแก้ไขหรือไม่ 2 คะแนน

สอดคล้องกับ OCP เพราะเพิ่ม Triangle(Shape) เป็นคลาสใหม่ได้ทันที
โดยไม่ต้องแก้โค้ดหลักที่เรียก area() เลยแม้แต่บรรทัดเดียว

2) Circle และ Rectangle สอดคล้องกับ Liskov Substitution Principle อย่างไร 2 คะแนน

Circle และ Rectangle แทนที่ Shape ได้ทุกที่โดยพฤติกรรมยังถูกต้อง
เพราะมี area() ที่คืนค่า float เสมอ จึงไม่ทำลายการทำงานของโค้ดหลัก

3) เทียบ interface ของ PHP กับ ABC ของ Python ว่ามีจุดเหมือน/ต่างกันอย่างไร 2 คะแนน

ทั้งคู่กำหนดสัญญาเมธอดที่ subclass ต้อง implement เหมือนกัน
แต่ ABC ของ Python มี attribute/บาง implementation ได้ ส่วน interface ของ PHP เป็นสัญญาล้วน ๆ
